Engineering notes

Why I built this site the boring way

July 26, 2026 · 4 min read

This site is a single folder of HTML, CSS and a little vanilla JavaScript. No React, no build step, no bundler, no framework that will be deprecated by the time you read this. That was a deliberate engineering decision, and I want to explain why — because it says something about how I think about systems.

Boring technology is a feature

A personal site has exactly one job: load fast, look good, and keep working for years with zero maintenance. The failure mode of a "modern" stack isn't that it can't do this — it's that in 18 months you return to a broken npm install, a dozen security advisories, and a build that no longer compiles. Static HTML on GitHub Pages has none of that surface area.

Choose the most boring technology that solves the problem. The novelty budget is better spent on the work itself.

What "best practices" actually bought me

Being boring didn't mean skipping the fundamentals. This site still does the things that matter:

  • Performance: one CSS file, one small JS file, system-friendly fonts. No render-blocking frameworks.
  • Accessibility: semantic landmarks, a skip link, visible focus states, and reduced-motion support.
  • SEO & sharing: Open Graph, Twitter cards, JSON-LD structured data, a sitemap and robots.txt.
  • Privacy: cookie-free analytics, so there's nothing to consent to.

The through-line

This is the same instinct I bring to enterprise platforms: understand the real requirement, reach for the simplest thing that satisfies it reliably, and spend complexity only where it earns its keep. A portfolio that still renders perfectly in 2030 is, quietly, the best demo of that philosophy I could ship.
